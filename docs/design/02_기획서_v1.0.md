## 1. 개요

### 1.1 한 줄 정의

팀원이 회의록(텍스트 또는 녹음 파일)을 올리면, AI가 회의 내용을 요약하고 실행할 할 일을 담당자·마감일과 함께 자동으로 뽑아주는 웹 서비스.

### 1.2 배경

사내 소규모 팀에서 회의는 자주 열리지만, 회의의 산출물은 개인의 메모에 머무르는 경우가 많다. 그 결과 회의에서 논의한 내용과 실제 실행 사이에 간극이 생긴다.

### 1.3 해결하려는 문제

| ID | 문제 | 현재 상황 | 기대 변화 |
|----|------|-----------|-----------|
| PB-01 | 회의록 정리에 시간이 오래 걸림 | 회의 후 담당자가 수기로 정리, 정리 자체가 부담이라 생략되기도 함 | 업로드만 하면 요약본이 자동 생성됨 |
| PB-02 | 할 일의 담당자가 흐지부지됨 | 구두로 정한 할 일이 기록되지 않거나 담당자가 불명확 | 할 일이 담당자·마감일과 함께 목록으로 남고 상태가 추적됨 |
| PB-03 | 지난 회의 내용을 다시 찾기 어려움 | 문서가 여러 곳에 흩어져 있어 검색이 어려움 | 한 곳에 쌓이고 검색으로 바로 찾을 수 있음 |

## 2. 목적과 목표

### 2.1 목적

회의가 끝난 뒤 "정리 → 할 일 분배 → 추적"으로 이어지는 흐름을 자동화하여, 회의 내용이 실행으로 이어지게 한다.

### 2.2 성공 지표 (KPI)

| ID | 지표 | 측정 방법 | 목표값 |
|----|------|-----------|--------|
| KPI-01 | 회의록 정리 소요 시간 | 도입 전후 사용자 설문 | 미정(결정 필요) |
| KPI-02 | 회의당 추출된 할 일 중 담당자가 지정된 비율 | 서비스 내 데이터 집계 | 미정(결정 필요) |
| KPI-03 | 주간 활성 사용자 비율(팀원 대비) | 로그인 로그 집계 | 미정(결정 필요) |
| KPI-04 | AI 추출 할 일의 사용자 수정 비율 | 추출 결과 대비 편집 건수 | 미정(결정 필요) |

> 목표 수치는 MVP 운영 데이터를 확보한 뒤 설정한다.

## 3. 대상 사용자

### 3.1 주요 사용자

사내 소규모 팀(5~10명). 별도 전담 서기 없이 팀원이 돌아가며 회의록을 작성하는 조직.

### 3.2 사용자 역할

| 역할 ID | 역할 | 설명 | 주요 권한 |
|---------|------|------|-----------|
| RL-01 | 팀 관리자 | 팀을 생성하고 팀원을 초대하는 사람 | 팀 설정, 팀원 초대·제외, 팀 내 전체 회의록 접근 |
| RL-02 | 팀원 | 회의록을 올리고 할 일을 수행하는 사람 | 회의록 업로드·조회·검색, 본인 할 일 상태 변경 |

> MVP에서는 두 역할만 둔다. 세분화된 권한(읽기 전용, 게스트 등)은 범위 밖.

### 3.3 사용자 시나리오

**시나리오 1 — 회의 직후 (PB-01, PB-02)**
팀원 A가 주간 회의를 마치고 녹음 파일을 업로드한다. 전사와 요약이 끝나면 할 일 목록이 자동으로 제시된다. A는 담당자가 비어 있는 항목만 지정하고 저장한다.

**시나리오 2 — 할 일 수행 (PB-02)**
팀원 B는 본인에게 배정된 할 일을 대시보드에서 확인하고, 완료 후 상태를 변경한다. 마감이 임박하면 알림을 받는다.

**시나리오 3 — 과거 회의 참조 (PB-03)**
팀 관리자 C가 특정 안건의 결정 경위를 확인하려 키워드로 검색해 해당 회의록과 요약을 찾는다.

## 4. 범위

### 4.1 이번 범위 (In Scope)

| FR ID | 기능 | 관련 문제 | 비고 |
|-------|------|-----------|------|
| FR-01 | 회의록 업로드 (텍스트 붙여넣기 / 파일 업로드) | PB-01 | 지원 형식은 03에서 확정 |
| FR-02 | 녹음 파일 자동 전사 (STT) | PB-01 | 외부 API 사용, 어댑터 구조 |
| FR-03 | AI 회의 요약 | PB-01 | 외부 API 사용, 어댑터 구조 |
| FR-04 | AI 할 일 자동 추출 (담당자·마감일 포함) | PB-02 | 추출 결과는 사용자가 수정 가능 |
| FR-05 | 할 일 담당자 지정 및 진행 상태 관리 | PB-02 | 상태값은 03에서 확정 |
| FR-06 | 지난 회의록 검색 | PB-03 | 검색 방식은 03에서 확정 |
| FR-07 | 팀 생성 및 팀원 초대 | PB-02 | 이메일 초대 방식 |
| FR-08 | 할 일 알림 (마감 임박 등) | PB-02 | 알림 채널은 03에서 확정 |

### 4.2 범위 밖 (Out of Scope)

| 항목 | 제외 사유 |
|------|-----------|
| 모바일 앱 (iOS/Android) | 웹만 지원. 개발 비용 대비 MVP 검증에 불필요 |
| 외부 도구 연동 (Slack, 캘린더, Jira 등) | 연동 설계·인증 부담이 크고 핵심 가설 검증과 무관 |
| 실시간 회의 참여·실시간 전사 | 업로드 기반으로 충분히 검증 가능 |
| 유료 결제·구독 관리 | 사내 사용 전제 |
| 세분화된 권한 체계 | 관리자/팀원 2단계로 충분 |
| 자체 호스팅 AI 모델 | 4.3 참조 |

### 4.3 AI 사용 방침 (중요 결정)

MVP 단계에서는 **외부 AI API를 사용**한다. 단, 추후 자체 호스팅 모델로 교체할 수 있도록 AI 연동부를 **교체 가능한 어댑터(인터페이스) 구조**로 설계한다.

- 적용 대상: FR-02(STT), FR-03(요약), FR-04(할 일 추출)
- 어댑터 경계: 애플리케이션 코드는 추상 인터페이스에만 의존하고, 특정 벤더 SDK를 직접 호출하지 않는다.
- 구체적 설계와 근거는 **08 시스템 아키텍처 + ADR**에 ADR로 기록한다.
- 사용할 외부 API 제공자: 미정(결정 필요)

## 6. 데이터 개요

| 데이터 | 개인정보 해당 | 비고 |
|--------|---------------|------|
| 계정 정보 (이름, 이메일) | 해당 | 로그인·초대·할 일 배정에 사용 |
| 회의록 본문 (텍스트) | 해당 가능 | 회의 중 언급된 인물 정보가 포함될 수 있음 |
| 녹음 파일 | 해당 가능 | 음성은 그 자체로 식별 가능 정보 |
| 요약·할 일 데이터 | 해당 가능 | 담당자 정보 포함 |

별도로 추가 수집하는 개인정보는 없다(직급·소속·프로필 사진 등 미수집). 수집 항목·보존기간·파기 절차는 **09 보안·개인정보 설계서**에서 확정한다.
