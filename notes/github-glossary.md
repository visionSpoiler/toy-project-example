# GitHub 용어사전

- 작성일: 2026-10-17
- 관련 기능/파일: 저장소 전반 (Git/GitHub 사용법)

## 배운 것

GitHub를 사용하면서 자주 마주치는 용어들을 정리했다.

### 기본 개념

- **Repository (저장소, 레포/repo)**: 프로젝트의 파일과 변경 이력을 담는 공간. 공개(public) 또는 비공개(private)로 설정할 수 있다.
- **Commit (커밋)**: 파일 변경 내용을 하나의 단위로 기록한 것. 각 커밋은 고유한 SHA 해시값을 가진다.
- **Branch (브랜치)**: 커밋 이력의 독립적인 흐름. 기본 브랜치는 보통 `main`. 기능 개발은 별도 브랜치에서 하는 것이 일반적.
- **Push**: 로컬(또는 에이전트)의 커밋을 원격 저장소(GitHub)로 올리는 것.
- **Pull**: 원격 저장소의 변경사항을 내 로컬로 가져오는 것.
- **Clone**: 원격 저장소 전체를 내 컴퓨터로 복사해오는 것.
- **Fork**: 다른 사람의 저장소를 내 계정으로 복사해 내 소유 저장소로 만드는 것. 오픈소스 기여할 때 많이 쓴다.

### 협업 관련

- **Pull Request (PR)**: 내 브랜치의 변경사항을 다른 브랜치(보통 main)에 병합해달라고 요청하는 기능. 코드 리뷰가 이 단계에서 일어날
  
- **Merge (병합)**: 두 브랜치의 변경사항을 하나로 합치는 작업. PR을 승인하면 일어나는 것이 보통적.
- **Merge Conflict (충돌)**: 두 브랜치에서 같은 부분을 다르게 수정해서 자동으로 병합할 수 없는 상황. 수동으로 해결해야 함.
- **Issue**: 버그, 개선 사항, 할 일 등을 기록하는 게시판 같은 기능.
- **Fetch**: 원격 저장소의 최신 정보를 가져오지만, 내 작업 브랜치에 자동 반영하지는 않는다. (pull = fetch + merge)

### 상태/저장 관련

- **Staging Area (스테이징 영역)**: 커밋할 파일을 미리 담아두는 공간. `git add`로 추가한다.
- **Working Directory**: 실제 파일을 수정하는 로컬 폴더.
- **HEAD**: 현재 체크아웃된 커밋/브랜치를 가리키는 포인터.
- **.gitignore**: Git이 추적하지 않을 파일/폴더를 지정하는 파일.
- **README**: 저장소의 대표 설명 문서. 저장소 메인 페이지에 자동으로 표시된다.

### 기타

- **Remote (원격)**: 내 로컬과 연결된 원격 저장소 주소. 기본 이름은 `origin`.
- **Tag**: 특정 커밋에 붙이는 이름표. 버전 릴리즈에 많이 쓴다. (예: v1.0.0)
- **Fork vs Clone 차이**: fork는 새 소유 저장소를 만드는 것, clone은 단순히 내 컴퓨터로 복사해오는 것.
- **Fast-forward**: 브랜치 히스토리가 일직선일 때, 병합 커밋 없이 포인터만 옮겨서 병합하는 방식.
